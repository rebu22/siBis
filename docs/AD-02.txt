PROMPT ACTIVITY DIAGRAM siBis — GAYA SWIMLANE 3 KOLOM (draw.io XML)
VERSI TEMPLATE (dipakai berulang untuk AD-01, AD-02, AD-03, dst.)
Cara pakai:
1. Salin seluruh isi file ini.
2. Isi BAGIAN I (DATA) dengan data activity yang baru. Hanya BAGIAN I yang
   berubah; bagian A sampai G dan BAGIAN J TIDAK diubah.
3. Tempel seluruhnya ke LLM. Hasilnya satu blok XML draw.io yang bisa
   ditempel lewat Extras > Edit Diagram, atau disimpan sebagai file .drawio.
Bila gambar acuan "Melakukan Login" ikut dilampirkan, ikuti juga bentuknya
(lane berkepala di atas, kotak sudut membulat, belah ketupat, garis tipis
berpanah).

Kamu adalah perancang UML. Tugasmu: menghasilkan SATU Activity Diagram
ber-swimlane dalam format draw.io XML untuk diagram pada BAGIAN I (DATA),
dengan bentuk dan pola tata letak yang SAMA seperti contoh pada BAGIAN J.
 
A. ATURAN OUTPUT
1. Keluarkan HANYA satu blok XML. Tanpa penjelasan, tanpa komentar, tanpa
   pagar kode (jangan pakai tiga backtick), tanpa teks pembuka/penutup.
2. Urutan elemen wajib:
   <mxfile host="app.diagrams.net"> -> <diagram name="..." id="..."> ->
   <mxGraphModel ...> -> <root> -> <mxCell id="0"/> -> <mxCell id="1" parent="0"/>
   lalu judul, tiga lane, seluruh node, dan seluruh edge.
3. Semua teks pada atribut value wajib di-escape: & menjadi &amp;,
   < menjadi &lt;, > menjadi &gt;, " menjadi &quot;. Baris baru di dalam
   satu value (hanya pada label edge) ditulis &lt;br&gt;, bukan newline.
4. Hitam-putih saja: fill putih, garis hitam (kecuali lingkaran dalam final
   node yang hitam penuh). Tanpa warna lain, tanpa bayangan, tanpa legenda.
5. Satu diagram hanya memuat satu use case dari BAGIAN I.
6. Teks node ditulis PERSIS seperti di BAGIAN I (termasuk nomor SRS di
   depan). Nama tabel ditulis polos (contoh: tabel users), tanpa backtick.

D. SIMBOL DAN UKURAN
1. Initial node: lingkaran 30x30, isi putih, garis hitam tebal 2, tanpa
   teks, x=120 (lane-aktor), y=115.
   ellipse;html=1;fillColor=#FFFFFF;strokeColor=#000000;strokeWidth=2;
2. Action: kotak putih SUDUT MEMBULAT, lebar 150. Tinggi 50 untuk teks 1-2
   baris, 56 untuk 3 baris, 64 untuk 4 baris atau lebih.
   rounded=1;arcSize=20;whiteSpace=wrap;html=1;fillColor=#FFFFFF;strokeColor=#000000;fontColor=#000000;fontSize=10;fontFamily=Helvetica;strokeWidth=1;
3. Decision: belah ketupat 130x80 (hanya di lane-sistem, x=350). Teks di
   dalamnya = kalimat kondisi dari BAGIAN I, tanpa tanda tanya.
   rhombus;whiteSpace=wrap;html=1;fillColor=#FFFFFF;strokeColor=#000000;fontColor=#000000;fontSize=9;fontFamily=Helvetica;strokeWidth=1;
4. Final node: DUA sel bertumpuk (buat luar dulu, lalu dalam):
   - luar: lingkaran putih 32x32, garis hitam tebal 2.
     ellipse;html=1;fillColor=#FFFFFF;strokeColor=#000000;strokeWidth=2;
   - dalam: lingkaran hitam penuh 20x20, tepat di tengah lingkaran luar
     (x_luar+6, y_luar+6).
     ellipse;html=1;fillColor=#000000;strokeColor=#000000;
5. Edge (garis tipis, panah segitiga isi):
   edgeStyle=orthogonalEdgeStyle;rounded=0;html=1;endArrow=block;endFill=1;strokeColor=#000000;strokeWidth=1;exitX=..;exitY=..;exitDx=0;exitDy=0;entryX=..;entryY=..;entryDx=0;entryDy=0;
   Sisi keluar/masuk: atas (0.5,0), bawah (0.5,1), kiri (0,0.5), kanan (1,0.5).
   Setiap edge punya source, target, edge="1", parent="1", dan anak
   <mxGeometry relative="1" as="geometry"> yang berisi
   <Array as="points"> dengan titik belok bila garis tidak lurus.
   Semua segmen garis harus tegak lurus (horizontal atau vertikal), dan
   tidak boleh menembus node lain.
6. Label cabang hanya pada edge keluar dari decision. Tulis polos tanpa
   kurung siku: "Ya", "Tidak", atau kondisi spesifik dari BAGIAN I
   (contoh: "Tidak - data tidak valid"). Tambahkan pada style edge:
   fontColor=#000000;fontSize=10;fontFamily=Helvetica;labelBackgroundColor=#FFFFFF;
   Label panjang dipecah dua baris dengan &lt;br&gt;. Geser label dengan
   <mxPoint x=".." y=".." as="offset"/> di dalam mxGeometry agar tidak
   menimpa node maupun garis lain.
 
E. ATURAN PEMETAAN LANE
1. Langkah pelaku (BAGIAN I, lane aktor) -> lane-aktor.
2. Langkah sistem -> lane-sistem. Pemanggilan layanan AI (LLM API) dan
   layanan email TETAP di lane-sistem, ditulis apa adanya.
3. Setiap operasi data (simpan/baca/ubah/hapus, termasuk Vector DB) ->
   lane-database, teks persis dari BAGIAN I.
4. Node penanganan exception (pesan kesalahan, penawaran ulang) ada di
   lane-sistem. Pesan sukses/arahan yang diterima pelaku boleh di lane-aktor.
5. Initial node di lane-aktor. Final node: jalur sukses di lane-aktor;
   jalur exception yang prosesnya berhenti di lane-sistem (kolom kanan).
 
F. ATURAN TATA LETAK DAN ROUTING EDGE
1. Node ditulis dengan parent = id lane-nya. Koordinat mxGeometry node
   RELATIF terhadap sudut kiri-atas lane: x_relatif = x_global - x_lane,
   y_relatif = y_global - 70. Edge selalu parent="1" dengan titik belok
   (mxPoint) dalam koordinat GLOBAL.
2. Baris vertikal (y_atas global): initial y=115, node pertama y=175. Setiap
   baris berikutnya turun sekitar 90 px (jarak tepi bawah ke tepi atas baris
   berikutnya minimal 30 px, setelah decision minimal 40 px). Dua node pada
   lane berbeda boleh berada pada baris yang sama (y tengah sama) bila
   langkah keduanya berurutan; di dalam SATU lane tidak boleh bertumpuk.
3. Pola edge antar langkah berurutan:
   P1 Satu lane, turun: bawah -> atas, lurus.
   P2 Lane berbeda, sebaris: sisi ke sisi, lurus tanpa titik belok
      (kanan -> kiri bila ke kanan; kiri -> kanan bila ke kiri).
   P3 Lane berbeda, baris lebih bawah: keluar bawah, masuk atas, dua titik
      belok pada y = tepi bawah sumber + 20: (x_sumber, y), (x_tujuan, y).
   P4 Keluar bawah, masuk dari samping node tujuan di lane lain: satu titik
      belok (x_sumber, y_tengah_tujuan).
   P5 Dari node lane-database ke node lane-sistem: keluar bawah node
      database, satu titik belok (x=695, y_tengah_tujuan), masuk sisi kanan
      node tujuan.
4. Decision:
   - Cabang "Ya" (jalur utama): keluar sisi kanan, lurus ke node lane-database
     yang sebaris (y tengah sama).
   - Cabang gagal pertama: keluar sisi kiri, satu titik belok
     (x_node_tujuan, y_tengah_decision), masuk atas node exception di kolom
     kiri lane-sistem, 40 px di bawah decision.
   - Cabang gagal kedua: keluar sisi bawah, dua titik belok pada
     y = tepi bawah decision + 20, masuk atas node exception di kolom kanan.
   - Bila decision hanya punya dua cabang: "Ya" ke kanan, "Tidak" keluar bawah
     ke node exception di kolom kanan (pola cabang gagal kedua).
5. Garis loop balik (kembali ke langkah sebelumnya), gaya edge sama, tidak
   putus-putus:
   - Ke node di lane-aktor: keluar sisi kiri node exception, belok ke x=135,
     lalu naik dan masuk dari BAWAH node tujuan.
   - Ke node di lane-sistem yang ada di atas: keluar sisi kanan node
     exception, belok ke x=590, naik, lalu masuk sisi kanan node tujuan.
6. Final node jalur exception diletakkan tepat di bawah node exception
   terakhir (x tengah sama, selisih y 24 px dari tepi bawah node).
7. Satu node = satu langkah/tabel. Ringkas, jangan mengulang langkah yang
   sama, jangan menambah langkah di luar BAGIAN I. Seluruh node harus
   berada di dalam lane-nya. Tinggi lane bawaan 950 (node terbawah berakhir
   sebelum y global 1020). Bila alur lebih panjang, naikkan tinggi KETIGA
   lane secara sama menjadi (y global tepi bawah node terbawah + 50 - 70),
   dan naikkan pageHeight agar muat.
8. Semua id sel unik: title, lane-aktor, lane-sistem, lane-database,
   n1, n2, ..., e1, e2, ... (edge pakai prefix e).
 
G. CHECKLIST SEBELUM MENJAWAB
- Judul + tepat 3 lane dengan id, header di atas, dan style sesuai C.
- Setiap node: parent = id lane-nya; setiap edge: parent="1".
- Seluruh baris BAGIAN I muncul dengan teks persis, tidak ada yang hilang
  atau ditambah.
- Semua edge punya source dan target yang valid, semua segmen tegak lurus,
  tidak ada garis yang menembus node.
- Label cabang hanya pada edge keluar decision, tanpa kurung siku.
- Final node = dua lingkaran bertumpuk (luar putih, dalam hitam).
- Setiap sel vertex punya anak <mxGeometry ... as="geometry"/>, dan setiap
  mxCell ditutup dengan benar.
- XML valid, semua id unik, tidak ada karakter mentah & < > di dalam value.

URUTAN ALIRAN — tulis teks node PERSIS seperti di bawah. Aturan nomor:
langkah yang ada pada tabel Flow of Activities SRS memakai nomor SRS-nya di
depan teks; langkah turunan (baris yang ditandai "tanpa nomor") tidak diberi
nomor.
 
1.  [aktor]  "<teks langkah pelaku>"
2.  [sistem] "<teks langkah sistem>"
3.  [DB]     "<teks operasi data>"
4.  [sistem][DEC] "<kalimat kondisi tanpa tanda tanya>"   (tanpa nomor)
...
n.  [aktor]  Final node jalur sukses
 
Kode lane: [aktor] = lane-aktor, [sistem] = lane-sistem, [DB] = lane-database,
[DEC] = decision (hanya di lane-sistem).
 
CABANG DECISION
- Dari node <no. decision>:
  * label "Ya" -> lanjut ke node <no.>
  * label "<kondisi gagal 1>" -> [sistem] "<teks node exception>" ->
    kembali ke node <no.> (garis balik)   ATAU   Final node di lane-sistem
  * label "<kondisi gagal 2>" -> [sistem] "<teks node exception>" -> ...
(ulangi untuk setiap decision)
 
ALIRAN UTAMA: initial -> 1 -> 2 -> ... -> n(final)
 
CATATAN BAGIAN I:
- Satu diagram = satu aktor. Bila alur melibatkan dua aktor, buat dua diagram.
- Decision maksimal 3 cabang (Ya + dua gagal); cabang "Ya" selalu jalur utama.
- Contoh BAGIAN I yang sudah terisi (AD-01) ada di akhir BAGIAN J sebagai
  gambaran format isian; jangan ikut dikerjakan.
